# UniStay App

Flutter-приложение UniStay для студентов и владельцев жилья. Ответственный — Турар Нурбаули. Основная ветка — main.

Приложение выделено в самостоятельный репозиторий с сохранением истории и авторства. lib/, test/, android/, ios/, web/ и pubspec.yaml находятся в корне. Серверных исходников и зависимости от соседней папки backend здесь нет.

**Состояние:** существующий Flutter-клиент перенесён. Новый [C# API](https://github.com/UniStay-Team/unistay-api) ещё предстоит написать, поэтому перенос не означает готовность сквозного D0. [Angular](https://github.com/UniStay-Team/unistay-admin) предназначен для администрации.

## Реализовано в клиенте

- Каталог, фильтры, сортировка, страницы и карточка с фотографиями/условиями.
- Регистрация студента, вход/выход, сессия, подтверждение почты и восстановление пароля.
- Профиль, согласие на показ соседям и отображение совместимости.
- Подача заявки, список, история и отмена; для владельца — вход и принятие/отклонение.
- Загрузка, ошибки, пустые состояния, повтор чтения и настройка адреса API.

Эти экраны требуют совместимого сервера. Unit/widget-тесты используют синтетические HTTP-ответы и не доказывают готовность нового backend.

## Запуск из корня репозитория

Flutter с Dart 3.11.1 или совместимой версией; зависимости зафиксированы в pubspec.lock.

```powershell
flutter pub get
flutter run -d chrome --web-port=3000 --dart-define=API_BASE_URL=http://127.0.0.1:8000
```

Перед реальным сценарием запустить API по его README. Для другого устройства выбрать ID из flutter devices:

```powershell
flutter run -d <device-id> --dart-define=API_BASE_URL=<server-root-url>
```

API_BASE_URL — корень без /api/v1. Сохранённая настройка в приложении имеет приоритет над параметром сборки. При смене хоста токен не переносится. Для release нужен HTTPS; адрес по умолчанию является заглушкой.

| Клиент | Локальный адрес API |
| --- | --- |
| Браузер на компьютере сервера | http://127.0.0.1:8000 |
| Android Emulator | http://10.0.2.2:8000 |
| Физический телефон | Доступный LAN-адрес сервера; localhost означает сам телефон |

API должен разрешать точный origin Flutter web через CORS. Для LAN нужны подходящие bind-адрес и firewall. На iOS для проверки нужны macOS/Xcode; предпочтителен HTTPS.

## Проверки

```powershell
flutter analyze
flutter test
flutter build apk --debug
flutter build web --dart-define=API_BASE_URL=https://api.example.test
```

Последний адрес — явная заглушка только для проверки сборки; перед реальным показом используется адрес работающего API.

[Проверки переноса](docs/transfer-validation.md). [VALIDATION.md](VALIDATION.md) сохраняет прежние результаты до разделения; они не являются проверкой C#.

Старый Python-runner и связанный с ним live-тест не входят в текущий запуск. Интеграционный набор для C# нужно реализовать по Q01–Q06/T01–T12 на изолированных демоданных.

Снимок синтетического интерфейса:

```powershell
flutter test tool/preview_test.dart
```

Результат — игнорируемая .local/. На Windows используется Segoe UI; для другой ОС задаются PREVIEW_FONT и при необходимости FLUTTER_ROOT. Это проверка вида экрана, не живая интеграция.

## Остаётся до V1

Регистрация владельца, создание/редактирование объявления, загрузка фото и полный кабинет владельца; интеграция всех существующих экранов с C#; тесты на Android и общий сценарий прав/занятости. Оплата, договоры, чат, отзывы и push в V1 не входят.

Android debug APK не является выпуском для магазина. Подпись release и публикация в магазинах не входят в текущую задачу.
